How it works

Everything an agent or a seller needs: the quote, the payment, the receipt, the errors and the rules we keep.

One call

  1. The agent sends POST /v1/buy/<item> with its JSON input and no payment. It gets 402 and a quote.
  2. The agent builds one Solana transaction from the quote, signs it and sends the same request again with the transaction, base64, in the X-Payment header.
  3. The gateway checks the transaction is exactly the quoted payment, signs it as fee payer and simulates it. Then it calls the seller.
  4. Only after the seller answers with 2xx is the transaction sent. When it confirms, the agent gets the answer and a receipt.

The kit does all of this in one call: bodega buy <item> key=value.

The quote

FieldMeaning
sellerAccount, sellerAmountThe seller's USDC account and what it gets, in units of 0.000001 USDC.
feeAccount, feeAmountThe fee wallet's USDC account and the fee. Zero when the seller holds the token.
feePayerOur key that pays the network fee and signs last. Your agent needs no SOL.
blockhashA recent blockhash, so the kit needs no RPC of its own. A payment lives about a minute.
refGoes in the memo, so each payment is unique.

The payment

One transaction, signed by the agent key and our fee payer, with these instructions and nothing else:

  • a compute unit limit, up to 40,000, and optionally a compute price up to 50,000 micro-lamports;
  • a USDC TransferChecked to the seller and one for the fee, both from the same account;
  • one memo, bodega:<ref>.

The agent key signs either as the owner of the USDC account or as its delegate. A delegate can spend only the allowance the owner set on the agents page.

The receipt

A paid call returns { item, result, receipt }. The receipt has the transaction, an explorer link, what was paid, what the seller got and the fee. The same receipt comes base64 in the X-Payment-Response header.

If the transaction was sent but has not confirmed in about 20 seconds, the call returns 202 with receipt: /v1/receipt/<tx>. The answer waits there for ten minutes and is handed over once the chain shows the payment. If it never lands, nothing was charged and no answer is given.

Rules

  • We never hold money. The buyer's USDC goes to the seller and the fee wallet in one transaction.
  • The fee is 3% of the price, taken from the seller's part. A seller holding the token pays none.
  • The seller carries one small risk: a buyer can empty the wallet between our check and the send. Then the seller answered for nothing. We check right before calling the seller to keep that short.
  • Every forwarded call is signed for the seller with HMAC-SHA256. See Sell here.
  • We can take an item off the shelf. Its owner cannot bring it back.
